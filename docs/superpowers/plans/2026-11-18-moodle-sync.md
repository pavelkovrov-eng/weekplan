# תוכנית: מטלות מהמודל אוטומטית (18.11.26)

## מטרה

מטלה חדשה שמרצה מעלה למודל מופיעה באפליקציה לבד, כהגשה עם תאריך, שעה וקורס, בלי מייל ובלי הדבקה.

**לא מטרות:** ציונים, הודעות פורום, הגשת קבצים, סנכרון חזרה למודל. **אנטי-מטרה:** מטלה שמחקתי חוזרת שוב, כפילויות, או המפתח האישי של המודל מגיע למקום ציבורי (הקוד, GitHub, לוגים).

## מה נבדק

- במודל של המכללה (`mama.mta.ac.il`) יש ייצוא לוח שנה כקישור קבוע (`/calendar/export_execute.php?userid=…&authtoken=…`), שמחזיר קובץ ICS.
- השרת עונה בלי `Access-Control-Allow-Origin`, אז הדף ב-`github.io` לא יכול לקרוא אותו. צריך צד שרת.
- הנתונים כבר ב-Supabase (התחברות עם Google, RLS). ל-Supabase יש Edge Functions באותו host, וה-CSP כבר מתיר אותו (`connect-src`).

## איך זה עובד

```
האפליקציה (sb)  ──JWT──▶  Edge Function "moodle"  ──▶  mama.mta.ac.il (ICS)
      ▲                         │ קוראת את הקישור מטבלת moodle_link (RLS, רק שלך)
      └──── אירועים מפוענחים ◀──┘
האפליקציה מחליטה מה חדש (core, עם בדיקות) ושומרת כהגשות דרך sbSave הרגיל
```

1. **הקישור:** בהגדרות, כרטיס חדש "המודל": מדביקים את הקישור פעם אחת. הוא נשמר בטבלה `public.moodle_link (user_id uuid primary key default auth.uid(), url text, updated_at)` עם RLS `user_id = auth.uid()`. הוא לא נכנס ל-`items`, לא למטמון המקומי ולא לגיבוי ב-GitHub. אחרי השמירה הכרטיס מראה רק "מחובר · סונכרן לפני 5 דק'" וכפתורים "סנכרון עכשיו" / "ניתוק".
2. **הפונקציה `moodle`:** מקבלת את ה-JWT של המשתמש, קוראת את הקישור שלו מהטבלה (עם אותו JWT, כך שה-RLS שומר), ובודקת שהוא בדיוק `https://mama.mta.ac.il/calendar/export_execute.php?...` (שום host אחר, כדי שאי אפשר יהיה להשתמש בה כפרוקסי). מורידה את ה-ICS, מפענחת `VEVENT`ים ומחזירה `[{uid, title, date, time, course}]`. לא שומרת כלום ולא כותבת את הקישור ללוג. אין בה מפתח service_role.
3. **מה חדש (core, טהור):** `moodleMerge(events, items, today)` → `{add:[docs], move:[{id,date,start}]}`:
   - כל הגשה שנוצרה מהמודל נושאת `mid` (ה-UID של האירוע). אירוע עם `mid` שכבר קיים לא נוסף שוב.
   - **מה שמחקת לא חוזר:** מסמך `kind:'moodle'` `{seen:[uid…], at}` (ב-`SPECIAL`, לא מצויר) זוכר כל UID שכבר נקלט. מחיקה של ההגשה לא מוחקת אותו מ-`seen`.
   - **התאמה להגשה שהוספת ידנית או מהדבקה** (אותו תאריך ואותו שם, כמו בהדבקה היום): לא נוספת שנייה; מקבלת `mid`.
   - **תאריך שזז במודל:** הגשה שעוד לא הוגשה זזה לתאריך החדש, עם הודעה "עודכן תאריך: …". הגשה שהוגשה לא נוגעים בה.
   - רק אירועים מ-`SEM.start` עד `SEM.last`, ורק מהיום והלאה (לא מעמיסים מטלות שעברו).
   - **קורס:** לפי `CATEGORIES` של האירוע (שם הקורס במודל) דרך `guessCourse`, ואם אין, לפי השם.
   - **שם:** בלי הקידומות של המודל ("יש להגיש את", "מועד הגשה", מרכאות).
4. **מתי:** בפתיחה של האפליקציה במצב `sb`, לכל היותר פעם ב-3 שעות (`at` במסמך `moodle`), ובכפתור "סנכרון עכשיו". הוספה של מטלות היא toast אחד: "נוספו 2 מטלות מהמודל". כשל (קישור פג, המודל לא עונה) הוא שקט בפתיחה, והודעה רק בלחיצה ידנית ובשורת המצב בכרטיס.

## בחנים

ה-ICS כולל גם פתיחה וסגירה של בחנים ("בוחן תרגיל 2 נפתח/נסגר"). ההצעה: לקלוט רק את הסגירה, כהגשה בשם "בוחן תרגיל 2". פתיחה, הרשמה לפגישות וכו' לא נקלטים. (אותו כלל נוסיף גם להדבקה הידנית: "תאריך הגשה בוחן …".)

## צעדים שאתה עושה (פעם אחת)

1. **מפתח חדש:** במודל, העדפות ← מפתחות אבטחה ← איפוס המפתח של לוח השנה (הקישור הקודם נשלח בצ'אט). ואז לוח השנה המלא ← ייצוא: "כל האירועים", "אירועים אחרונים וקרובים" ← "קבלת כתובת לוח השנה".
2. **ב-Supabase (Dashboard):**
   - SQL Editor: להריץ את הקובץ `supabase/moodle_link.sql` (אכין: הטבלה, ה-RLS וה-grant).
   - Edge Functions: ליצור פונקציה `moodle` ולהדביק את `supabase/functions/moodle/index.ts` (אכין), Deploy. הגדרה "Verify JWT" נשארת דולקת.
3. **באפליקציה:** הגדרות ← "המודל" ← הדבקת הקישור החדש.

את הקישור לא שולחים בצ'אט; הוא נכנס רק לשדה באפליקציה.

## שלבים (כל שלב: בדיקות, ורק אחרי אישורך פרסום)

1. **core + בדיקות:** `parseIcs(text)` (שורות מקופלות, `TZID`/UTC → שעון ישראל, `CATEGORIES`, תווים מוברחים), `moodleTitle`, `moodleMerge`. בדיקות על ICS לדוגמה בפורמט של Moodle. `mid` ו-`kind:'moodle'` נשמרים ב-`toDoc`/`SPECIAL`.
2. **Supabase:** `supabase/moodle_link.sql` + `supabase/functions/moodle/index.ts` (Deno, ~60 שורות, ה-parser עובר בצד השרת רק לפירוק ה-ICS ל-JSON). בדיקה: אתה מריץ ב-Dashboard, אני בודק מהאפליקציה בתצוגה מקדימה מול פונקציה מזויפת (`fetch` stub), אף פעם לא מול המודל האמיתי עם המפתח שלך.
3. **אפליקציה:** כרטיס "המודל" בהגדרות, סנכרון בפתיחה, toast, `mid` בהגשות. בדיקה בסימולטור עם stub.
4. **ניסיון אמיתי (אתה):** מדביק את הקישור החדש, לוחץ "סנכרון עכשיו", ואנחנו בודקים ביחד מה נכנס (שמות, קורסים, שעות). תיקונים לפי מה שה-ICS האמיתי מחזיר.
5. **תיעוד:** `CLAUDE.md`.

## סיכונים

- **פורמט ה-ICS בפועל** (שמות האירועים, `CATEGORIES`, שעות) ידוע רק אחרי שלב 4; ה-parser נכתב לפורמט הסטנדרטי של Moodle, וייתכנו תיקונים קטנים.
- **המפתח פג** (איפוס, שינוי סיסמה במכללה): הכרטיס יראה "הקישור לא עובד, צריך חדש".
- **רק במצב Supabase:** במצב שרת מקומי / GitHub / דפדפן בלבד הכרטיס מוסתר.
- **סטודנטים אחרים:** כל אחד מדביק את הקישור שלו; הטבלה וה-RLS כבר לפי משתמש.
