# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal weekly planner for semester A, תשפ"ז (18.10.26–15.01.27, exams through 08.03.27), at the Academic College of Tel Aviv-Yaffo (MTA), BA in Economics & Management. The whole app is one self-contained HTML file: `index.html`. It runs locally, served by `server.py` (see below). A legacy copy is published as a claude.ai Artifact: https://claude.ai/artifact/F2qwDgUBPhPYNDU3Z2DiZg, declaring the capabilities `db`, `user` and `downloads`.

The UI is Hebrew and RTL. The user writes in Hebrew.

## Build / run / deploy

- There is no build step, package manager or linter. Edit the HTML file directly. Python is stdlib only (3.14 here).
- **Run (primary way):** double-click `start.command`, or `python3 server.py`. The URL is printed in the terminal and the browser opens on it. Closing the terminal stops the server. Flags: `--port N` (exactly that port, no scanning), `--no-browser`, `--data-dir DIR` (default `data`). The status pill reads "נשמר במחשב".
- **Server** (`server.py`) binds 127.0.0.1 only and serves fixed routes (everything else 404; 403 on a bad `Host`, 501 for other methods): `GET /` (the page, read from disk on every request), the PWA shell files in `STATIC` (`/manifest.webmanifest`, `/sw.js`, `/icon-192.png`, `/icon-512.png`, `/apple-touch-icon.png`; fixed names, GET only), `GET /api/ping`, `GET|POST /api/items`, `PUT|DELETE /api/items/<id>`. Guards: the `Host` header must be `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding); writes need `Content-Type: application/json` and, if `Origin` is present, it must be the server's own; bodies over 1 MiB get 413.
- **Port:** by default the range 8010..8029. First the whole range is probed: if any port answers `/api/ping` as `weekplan`, the planner is already running, so the browser opens on it and the new process exits. Otherwise it binds the first port nothing is listening on (a quick relaunch keeps its port; a wildcard `0.0.0.0` listener counts as busy). With `--port N` it uses exactly N: planner there → open and exit 0; something else there → a Hebrew error and exit 1. If nothing can start, the output is one Hebrew line and exit 1, not a traceback.
- **Storage:** SQLite `data/weekplan.db` (git-ignored; `--data-dir` moves it). At every start the db is snapshotted to `<data-dir>/backups/` (newest 20 kept).
- **Tests:** `node --test test.mjs` (single: `node --test --test-name-pattern="<name>" test.mjs`) and `python3 -m unittest -v test_server.py`. The Node tests evaluate `<script id="core">` from the HTML in Node — keep everything in core pure (no DOM / localStorage at top level). The harness exports the top-level `const`/`function` names found at the start of a line, one name per `const` line (hence `clampSun` on its own line).
- **GitHub mode (`gh`):** the page opened from `*.github.io`, or with `localStorage['wp.gh']` set, stores `items.json` in a private repo through the Contents API (see Architecture). Test it with a stub: serve a scratch copy of `index.html` over http (the browser pane shows `file://` as a static snapshot) whose `<head>` first defines `window.fetch` as a fake Contents API (GET 200/404, PUT 200, a 409, 401, a network error). Never use a real token or `api.github.com`.
- **PWA shell (for GitHub Pages and the iPhone Home Screen):** `manifest.webmanifest`, `sw.js`, the PNG icons (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, generated by `python3 tools/make_icons.py`, stdlib only; the colours are the `--accent` tokens) and `.nojekyll` sit next to `index.html`. The `<head>` (line 1 of `index.html`, a CSP `<meta>` only counts inside `<head>`) links the manifest and icons and carries a CSP: `default-src 'self'`, inline script/style allowed (the app is inline), `connect-src 'self' https://api.github.com`, Google Fonts allowed in `style-src`/`font-src`, `img-src 'self' data:`. A new third-party host (or a `blob:`/`data:` use) needs a CSP edit, and a violation shows in the console as "violates the following Content Security Policy directive". `sw.js` precaches the shell (`SHELL`, cache `V`), is network-first with `cache:'no-cache'` and a 5 s timeout, falls back to the cache offline, and only touches same-origin GETs outside `/api/`, so `api.github.com` and the fonts are never cached by it. It is registered only on `https:` (never on localhost or `file:`), so test its logic by reading it or by a Node stub, not in the preview. Adding a file to the shell means: add it to `SHELL` and bump `V`, and to `STATIC` in `server.py`.
- **Preview a phone:** resize the browser pane with `resize_window` to 393×852 (and `colorScheme` light/dark). A hidden pane never fires `matchMedia` `change` events, so to test the desktop↔phone switch call `PHQ.dispatchEvent(new Event('change'))` after resizing. Swipes can be tested by dispatching `TouchEvent`s on `#dayCard`.
- **Preview without the server:** open the file in the browser pane. `window.claude` is missing there, so the page falls back to `localStorage` mode and the pill reads "נשמר בדפדפן הזה בלבד".
- **Preview with the server:** `.claude/launch.json` → `weekplan` runs `python3 server.py --no-browser --port 8765 --data-dir .preview-data`. Test items go to `.preview-data/` (git-ignored), never to the real `data/`.
- **Legacy claude.ai artifact:** the page still works there (`window.claude` db) but has separate data and is no longer used. To republish, use the Artifact tool with `url` = the artifact URL above, `file_path` = the HTML file and `capabilities:{db:{},user:{},downloads:true}`. When passing `capabilities` on publish, list all three: a non-empty object replaces the stored set, and omitting it keeps the stored set. The published version may differ from the local file: read it with `Artifact action:"read"` and merge first. The CSP `<meta>` added for the PWA shell was never tried on claude.ai; its `connect-src` may block whatever the `window.claude` runtime fetches, so check the artifact after republishing.

## Architecture (single file, three parts)

1. **CSS.** Design tokens are defined on `:root`. Dark mode repeats the same token set twice: once under `@media (prefers-color-scheme:dark){:root:not([data-theme="light"])}` and once under `:root[data-theme="dark"]`. A new color must be added in all three places. Course colors are `--c-<course>` tokens plus `--on-course` (ink on solid exam blocks); a class/exam block gets class `c-<course>`, which sets `--cc`, and its tints are `color-mix` of `--cc`. Personal shift kinds keep `--X-bg/--X-bd/--X-tx` triples. Layout uses logical properties (`inset-inline-*`, `padding-inline`) so RTL works.
2. **Markup.** The page is a header, the week bar (`#prev` →, range `#wkLabel`, rotation tag `#rotBtn`, `#next` ←, `#todayBtn`, the week/month toggle `#vWeek`/`#vMonth`, `#addBtn`), the anchor banner `#anc` (shown only in editable modes while no rotation anchor exists), the "what's coming" card `#up`, a summary strip `#sum`, an attention list `#att`, a dated 7-day grid `#grid` (in card `#gridCard`) running Sunday to Saturday, a per-day agenda `#agenda` (card `#agCard`), a month calendar `#month` (in card `#monthCard`, shown instead of `#sum`, `#att`, `#gridCard` and `#agCard` in month mode), the single print bar `.printbar` with `#printBtn` and `#printFile` (render() moves it into whichever of the two cards is shown), the export card `#expCard` (`#expCsv`, `#expIcs`), the add/edit `<dialog id="dlg">`, and `#toast`. The phone layout adds the day card `#dayCard` (week strip `#dstrip`, day notes `#dayHead`, line list `#dayList`), the week-tab toggle `#wkBar`/`#gridTgl`, and the bottom tab bar `nav#tabs` (`button[data-v]` = `day|week|month|up`, inline SVG icons); the tab bar and the phone-only rules are hidden or inert unless `<html>` has class `ph`.
3. **Script.** Two tags; data flows in one direction.
   - **`<script id="core">`** is pure (tests run it in Node). It holds the constants, the date helpers, the locked data, the model functions and the export builders:
     - Locked data (changes only in code): `BASE` is the course timetable (day index, start, end, title, kind `lec|tut|lab|eng`, room); `COURSE` maps a course title to its color id. `SEM` is `{start,end,last}`. `CAL` marks days off (`off`) and the make-up day (`as`: which weekday's timetable it runs). `EXAMS` lists moed א/ב per course with date and start; `EXAM_MIN` is an assumed 3h.
     - Dates are ISO `YYYY-MM-DD` strings, computed with `Date.UTC` so DST never shifts a day: `addDays`, `dow`, `sunOf`, `dm`, `todayIso` (Asia/Jerusalem). Month helpers: `MONTHS` (Hebrew names), `CSHORT` (short course names), `YM0`/`YM1` (navigable month range), `ymOf`, `addMonths`, `clampYm`, `monthSuns(ym)` (the Sundays of the month's week rows).
     - Model: `anchorOf(items)` and `rot(sun,anchor)` give the A/B rotation of a week (`null` until an anchor is set). `baseDay(iso,items)` says whose timetable runs on a date, or `null`; a manual `off` doc is checked before `CAL[iso].as`. `evsForWeek(sun,items,skipId)` merges BASE, exams and items into events `{src:'base'|'exam'|'user',key,d,date,s,e,...}` (base/exam events carry `course`; a base event has `i`, its BASE index, and `cancelled:true` when a `kind:'cancel'` doc matches it, and `analyze`, `stats` and `semEvents` ignore cancelled events); `skipId` leaves out the item being edited. Then `analyze(evs,nextSun)` finds clashes (hard) and tight gaps under 30 minutes or late nights (soft; `nextSun` is the following Sunday's events, for the Saturday late-night check), and `stats()` computes the summary totals. `upcoming(today,items)` returns the next exams and unfinished deadlines with `daysLeft`. Phone helpers: `DAYI` (day initials), `clampDay` (navigable days, `SEM.start..SEM.last`), `pickDay(cur,lo,hi,today)` (the day to land on when a week or month is shown: the pick if inside, else today, else the first day), `swipeDir(dx,dy)` (±1 or 0; ≥50px and mostly horizontal; Hebrew/RTL as on iOS, so a swipe to the right is the next day), `dayLines(date,items,evs?)` (one date by time: `evsForWeek` events plus deadlines as `src:'due'` lines) and `lineTxt(line)` (`{col,ttl,meta}`, shared by the agenda and the day list). `toDoc(form,sun)` builds the db doc from the dialog; `detach(prev,f,sun,occ)` turns one occurrence of a recurring item into a one-off or deadline (new dated doc plus `skip` on the series).
     - Export: `semEvents` (every occurrence from `SEM.start` to `SEM.last`), `buildIcs` (one VEVENT per occurrence, `TZID=Asia/Jerusalem` with a VTIMEZONE block), `buildCsv` (Google import format), `zip1` (one stored, uncompressed file; `.ics` is not on the downloads allowlist, `.zip` is).
   - **Phone layout:** `PHQ = matchMedia('(max-width:600px)')` (width only, not `display-mode`; an iPhone turned sideways gets the desktop layout); `render()` toggles class `ph` on `<html>` from it and a `change` listener re-renders (a desktop falls back from `day`/`up` to `week`, not persisted). On a phone `view` is `day|week|month|up`: `day` (default on first run) shows `#dayCard`; `week` shows `#sum`, `#att` and the agenda `#agCard`, or the wide grid `#gridCard` while `wkGrid` (the `#gridTgl` toggle) is on; `month` shows the month with dots only (CSS under `.ph` hides the line text; `.ml` has `pointer-events:none`, so any tap in a cell reaches `dayClick`, which opens the day view); `up` shows only `#upCard` (30 items, a tap opens that day). `viewDay` is the picked ISO date; `goDay(d)` keeps `viewDay`, `viewSun` and `viewYm` in step, so the week and month tabs open on the picked day. `setView(v,date)` handles the tab bar (`date` opens the day view on that date; `up` is never stored in `wp.view`); `step(n)` is the prev/next/swipe move for the current view. In the day view `#dayList` lines are one `button[data-key]` each (`dayL` holds the lines): a class opens `openCancel`, an own item or deadline opens `openEdit`, exams (and classes in read-only modes) are plain `div`s; a deadline line has a 44px done checkbox (`data-done`). `#addBtn` becomes the round fixed button on a phone (day: `openAdd({day:dow(viewDay)})`, `viewSun` is already the picked day's week); `#addBtn` and `.nav` are hidden in the `up` tab. Touch targets are ≥44px, inputs are 16px (iOS zooms into smaller ones). No new color tokens.
   - **App script** (after core): `viewSun` is the Sunday of the shown week. It starts at the current week, is not persisted, and `clampSun` keeps it within `SEM.start..sunOf(SEM.last)`. `go(sun)` changes it. `view` is `week|month` on a desktop (kept in `localStorage['wp.view']`, in try/catch; a stored `day` is ignored there) and `viewYm` is the shown `YYYY-MM` (clamped to `YM0..YM1`); `setView()` week→month takes the month of `viewSun`, month→week leaves `viewSun`. `renderMonth()`/`monthCell()` draw the month: one `button` per line (`data-kind` = `base|exam|user|due|more`, plus `data-date`, `data-id` or `data-i`), at most 5 lines per cell then "+N עוד"; recurring shifts and A/B tags also show outside the semester. One delegated listener on `#month`: a user or deadline line opens `openEdit(id, sun)` and a class line opens `openCancel` (both only if `canEdit()`); anything else (day number, empty cell space, exam, "+N עוד") calls `dayClick(date)`, which switches to week view on that week. `#addBtn` in month mode opens `openAdd({sun})` for today's week, or the week of the 1st if today is not in the shown month. Print: `@media print` + `@page` (A4 landscape) show only the shown card, `#gridCard` or `#monthCard` (the hidden one stays `hidden`), so Ctrl+P works in both views; `beforeprint` forces `data-theme=light` and sets `--ps` (a `zoom` that fits one page); `#printFile` offers a standalone `weekplan-<sunday>.html` (month: `weekplan-<YYYY-MM>.html`) that prints itself. `render()` redraws everything from scratch; there is no incremental DOM update. `layout()` assigns overlap lanes inside a day column.
   - **GitHub storage (`gh`):** `wp.gh` = `{owner,repo,token}` (defaults `pavelkovrov-eng` / `weekplan-data`), edited in `#ghDlg` (footer link "חיבור ל-GitHub", hidden in `srv` and `db`; התנתקות removes `wp.gh` and `wp.gh.cache`, then reloads). The file is `items.json` = `{"v":1,"items":{"<id>":{...doc}}}`, pretty-printed; ids are 20 hex chars from `newId()`. Core helpers: `b64enc`/`b64dec` (UTF-8, tolerate GitHub's wrapped base64), `storeToItems`/`itemsToStore`, `applyOp(store,{id,doc})` (`doc:null` deletes), `storeValid` (only `{v:1,items:{…}}`), `opNoop` (skip the PUT when an op changes nothing). App script: `ghLoad()` (GET; a 404 on the file counts as an empty store only if `GET /repos/{owner}/{repo}` answers 200, otherwise it is treated as 403 because a private repo the token cannot see also gives 404; a file that is not a valid store sets `ro` and is never overwritten; also the refresh on `visibilitychange` and `online`), `ghSave(op)` (PUT with the last `sha`, on 409 or a 422 that mentions sha re-GET, re-apply the op, up to 3 retries), `ghStart()`. `ghSeq` drops a GET that a newer GET or a save overtook. Every good load or save refreshes `wp.gh.cache` = `{repo,items,sha,at}` (a cache of another `owner/repo` is ignored); if a load fails and a cache exists the page shows it in `ro`. 401/403 toasts and opens `#ghDlg`.
   - **`items` docs** (collection `items`) are told apart by their fields:
     - recurring `{kind,title,day,start,end,week:'A'|'B'|'both',note,updated,skip?:[iso…]}`; `skip` lists dates the item is skipped.
     - one-off: same, but with `date` instead of `day`/`week`.
     - `kind:'due'` `{title,date,start,note,done}`: a deadline, not drawn in the grid; shown in the day header, agenda and "what's coming".
     - `kind:'off'` `{date}`: cancels the BASE classes of that date only.
     - `kind:'cancel'` `{date,base}`: one cancelled class, `base` is the BASE index (also on the make-up day); the class stays drawn, faded and struck through, but is not counted, clashed or exported.
     - `kind:'anchor'` `{date}`: the Sunday of an A week; the newest by `updated` wins.
     - A user block has `KINDS` set to `open|close|study|due|other`.
   - **Time model:** minutes since midnight. An `end` at or before `start` means the block ends after midnight (`span()` adds 1440). The grid can extend past 24:00, up to 27:00.
   - **Storage modes:** `mode` is one of `loading | srv | gh | db | local | ro`. Detection order: (1) on `http://127.0.0.1` or `localhost` the page tries `fetch('/api/items')`; on success it runs in `srv` mode against the local server; (2) on a `*.github.io` host, or if `wp.gh` exists, `gh` mode (no config: `#ghDlg` opens and the mode stays `loading`); (3) `window.claude`; (4) `local`. `canEdit()` accepts `srv`, `gh`, `db` and `local`. In `db` mode the page uses `window.claude.use('db')`, collection `items`, with a live `onSnapshot` listener. If `user.can('data.write') === false` the mode is `ro`. Without `window.claude` the page uses `localStorage` key `wp.items.v1`. Every db write goes through `dbCall()`, which maps error codes to Hebrew toasts. Downloads go through `offer()`: `window.claude.use('downloads').save({filename,data})`, falling back to `a[download]` in `local`, `srv` and `gh` modes.

The local db (`data/weekplan.db`) holds the user's real shifts. Any schema change must still read the existing docs: they have `week` and no `date` or `skip`, and they keep working as recurring items.

## Conventions

- All user-facing copy is Hebrew. Pass user strings through `esc()` before writing them to `innerHTML`.
- The code is compact: short helpers (`$`, `pad`, `fm`, `tr`, `hrs`) and long one-line expressions. Match that style rather than reformatting.
- Delete takes two clicks (`delArmed`); there is no undo.
