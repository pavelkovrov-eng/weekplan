# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal weekly planner for semester A, תשפ"ז (18.10.26–15.01.27, exams through 08.03.27), at the Academic College of Tel Aviv-Yaffo (MTA), BA in Economics & Management. The whole app is one self-contained HTML file: `index.html`. It runs locally, served by `server.py` (see below). A legacy copy is published as a claude.ai Artifact: https://claude.ai/artifact/F2qwDgUBPhPYNDU3Z2DiZg, declaring the capabilities `db`, `user` and `downloads`.

The UI is Hebrew and RTL. The user writes in Hebrew.

## Build / run / deploy

- There is no build step, package manager or linter. Edit the HTML file directly. Python is stdlib only (3.14 here).
- **Run (primary way):** double-click `start.command`, or `python3 server.py`. The URL is printed in the terminal and the browser opens on it. Closing the terminal stops the server. Flags: `--port N` (exactly that port, no scanning), `--no-browser`, `--data-dir DIR` (default `data`). The status pill reads "נשמר במחשב".
- **Server** (`server.py`) binds 127.0.0.1 only and serves fixed routes (everything else 404; 403 on a bad `Host`, 501 for other methods): `GET /` (the page, read from disk on every request), the PWA shell files in `STATIC` (`/manifest.webmanifest`, `/sw.js`, `/icon-192.png`, `/icon-512.png`, `/apple-touch-icon.png`; fixed names, GET only), `GET /api/ping`, `GET|POST /api/items`, `PUT|DELETE /api/items/<id>`. Guards: the `Host` header must be `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding); writes need `Content-Type: application/json` and, if `Origin` is present, it must be the server's own; bodies over 1 MiB get 413.
- **Port:** by default the range 8010..8029. First the whole range is probed: if any port answers `/api/ping` as `weekplan`, the planner is already running, so the browser opens on it and the new process exits. Otherwise it binds the first port nothing is listening on (a quick relaunch keeps its port; a wildcard `0.0.0.0` listener counts as busy). With `--port N` it uses exactly N: planner there → open and exit 0; something else there → a Hebrew error and exit 1. If nothing can start, the output is one Hebrew line and exit 1, not a traceback.
- **Storage:** SQLite `data/weekplan.db` (git-ignored; `--data-dir` moves it). At every start the db is snapshotted to `<data-dir>/backups/` (newest 20 kept).
- **Tests:** `node --test test.mjs` (single: `node --test --test-name-pattern="<name>" test.mjs`) and `python3 -m unittest -v test_server.py`. The Node tests evaluate `<script id="core">` from the HTML in Node — keep everything in core pure (no DOM / localStorage at top level). The harness exports the top-level `const`/`function` names found at the start of a line, one name per `const` line (hence `clampSun` on its own line).
- **GitHub mode (`gh`):** the page opened from `*.github.io`, or with `localStorage['wp.gh']` set, stores `items.json` in a private repo through the Contents API (see Architecture). Test it with a stub: serve a scratch copy of `index.html` over http (the browser pane shows `file://` as a static snapshot) whose `<head>` first defines `window.fetch` as a fake Contents API (GET 200/404, PUT 200, a 409, 401, a network error). Never use a real token or `api.github.com`.
- **PWA shell (for GitHub Pages and the iPhone Home Screen):** `manifest.webmanifest`, `sw.js`, the PNG icons (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, generated by `python3 tools/make_icons.py`, stdlib only; the colours are the `--accent` tokens) and `.nojekyll` sit next to `index.html`. The `<head>` (line 1 of `index.html`, a CSP `<meta>` only counts inside `<head>`) links the manifest and icons and carries a CSP: `default-src 'self'`, inline script/style allowed (the app is inline), `connect-src 'self' https://api.github.com`, Google Fonts allowed in `style-src`/`font-src`, `img-src 'self' data:`. A new third-party host (or a `blob:`/`data:` use) needs a CSP edit, and a violation shows in the console as "violates the following Content Security Policy directive". `sw.js` precaches the shell (`SHELL`, cache `V`), is network-first with `cache:'no-cache'` and a 5 s timeout, falls back to the cache offline, and only touches same-origin GETs outside `/api/`, so `api.github.com` and the fonts are never cached by it. It is registered only on `https:` (never on localhost or `file:`), so test its logic by reading it or by a Node stub, not in the preview. Adding a file to the shell means: add it to `SHELL` and bump `V`, and to `STATIC` in `server.py`.

## Architecture (single file, three parts)

1. **CSS.** Design tokens are defined on `:root`. Dark mode repeats the same token set twice: once under `@media (prefers-color-scheme:dark){:root:not([data-theme="light"])}` and once under `:root[data-theme="dark"]`. A new color must be added in all three places. Course colors are `--c-<course>` tokens plus `--on-course` (ink on solid exam blocks); a class/exam block gets class `c-<course>`, which sets `--cc`, and its tints are `color-mix` of `--cc`. Personal shift kinds keep `--X-bg/--X-bd/--X-tx` triples. Layout uses logical properties (`inset-inline-*`, `padding-inline`) so RTL works.
2. **Markup.** The page is a header, the week bar (`#prev` →, range `#wkLabel`, `#next` ←, `#todayBtn`, the week/month toggle `#vWeek`/`#vMonth`, `#addBtn`), then the cards in this order: the calendar first, either a dated 7-day grid `#grid` (in card `#gridCard`) running Sunday to Saturday or a month calendar `#month` (in card `#monthCard`, shown instead of `#sum`, `#att`, `#gridCard` and `#agCard` in month mode); then a summary strip `#sum` and an attention list `#att`; then the "what's coming" card `#upCard` (a `<details>`: closed on every page load, its closed line `#upSum` shows the late count and the next date; the phone `up` tab opens it in `setView`; the list `#up`, the submitted record `#upDone`, the paste button `#pasteBtn`); then the per-day agenda `#agenda` (card `#agCard`, "פירוט לפי יום") (a `<details class="card">` like `#upCard`); the shifts summary `#shCard` and the export card `#expCard` now live in the settings dialog `#setDlg` (header button `#setBtn` ⚙️; sections: profile `#obLink`, shifts, export, my data = JSON backup `#setBackup` + two-click wipe `#setWipe`, account/privacy with the GitHub and Google links), not in the page; the footer has no links (closed on every page load; the closed line `#agSum`/`#shSum` shows the week's range with shift and deadline counts / this month's shift hours; on a phone the week tab shows the two-day grid `#gridCard` (columns of half the width, `scroll-snap-type:x mandatory`, a sticky hour axis; no grid toggle any more) and the agenda stays a closed card below it); then the export card `#expCard` (also a closed-by-default `<details class="card">`, closed line "Google Calendar · Apple"); the single print bar `.printbar` with `#printBtn` and `#printFile` (render() moves it into whichever of the two cards is shown), the export card `#expCard` (`#expCsv`, `#expIcs`), the add/edit `<dialog id="dlg">`, and `#toast`. The phone layout adds the day card `#dayCard` (week strip `#dstrip`, day notes `#dayHead`, line list `#dayList`), the week-tab toggle `#wkBar`/`#gridTgl`, and the bottom tab bar `nav#tabs` (`button[data-v]` = `day|week|month|up`, inline SVG icons); the tab bar and the phone-only rules are hidden or inert unless `<html>` has class `ph`.
3. **Script.** Two tags; data flows in one direction.
   - **`<script id="core">`** is pure (tests run it in Node). It holds the constants, the date helpers, the locked data, the model functions and the export builders:
     - Locked data (changes only in code): `BASE` is the course timetable (day index, start, end, title, kind `lec|tut|lab|eng`, room; `self:1` marks a class with no frontal meeting, now only the OB lecture, self-paced on Zoom since 2026-11: `evsForWeek` never emits it, but the entry stays because `kind:'cancel'` docs store BASE indices); `COURSE` maps a course title to its color id. `SEM` is `{start,end,last}`. `CAL` marks days off (`off`) and the make-up day (`as`: which weekday's timetable it runs). `EXAMS` lists moed א/ב per course with date and start; `EXAM_MIN` is an assumed 3h.
     - Dates are ISO `YYYY-MM-DD` strings, computed with `Date.UTC` so DST never shifts a day: `addDays`, `dow`, `sunOf`, `dm`, `todayIso` (Asia/Jerusalem). Month helpers: `MONTHS` (Hebrew names), `CSHORT` (short course names), `YM0`/`YM1` (navigable month range), `ymOf`, `addMonths`, `clampYm`, `monthSuns(ym)` (the Sundays of the month's week rows).
     - Model: there is no week-A/B rotation any more (removed 2026-11; `rot`/`anchorOf` are gone): a recurring item (`isRec`: `week` is `'both'`, or `'A'`/`'B'` from docs of the old rotation) shows every week, and `kind:'anchor'` docs are ignored (`SPECIAL`). `baseDay(iso,items)` says whose timetable runs on a date, or `null`; a manual `off` doc is checked before `CAL[iso].as`. `evsForWeek(sun,items,skipId)` merges BASE, exams and items into events `{src:'base'|'exam'|'user',key,d,date,s,e,...}` (base/exam events carry `course`; a base event has `i`, its BASE index, and `cancelled:true` when a `kind:'cancel'` doc matches it, and `analyze`, `stats` and `semEvents` ignore cancelled events); `skipId` leaves out the item being edited. Then `analyze(evs,nextSun)` finds clashes (hard) and tight gaps under 30 minutes or late nights (soft; `nextSun` is the following Sunday's events, for the Saturday late-night check), and `stats()` computes the summary totals. `upcoming(today,items)` returns the next exams and unfinished deadlines with `daysLeft`. Phone helpers: `DAYI` (day initials), `clampDay` (navigable days, `SEM.start..SEM.last`), `pickDay(cur,lo,hi,today)` (the day to land on when a week or month is shown: the pick if inside, else today, else the first day), `swipeDir(dx,dy)` (±1 or 0; ≥50px and mostly horizontal; Hebrew/RTL as on iOS, so a swipe to the right is the next day), `dayLines(date,items,evs?)` (one date by time: `evsForWeek` events plus deadlines as `src:'due'` lines) and `lineTxt(line)` (`{col,ttl,meta}`, shared by the agenda and the day list). `shiftMonths(items)` totals the user's own shift blocks (`KINDS[kind].shift`) per month, `YM0..YM1` (`{rows:[{ym,min,n}],min,n}`; one-off shifts count from the 1st of the first month, so past shifts from the attendance report can be entered via the API even though the dialog only picks dates from `SEM.start`; recurring series only from `SEM.start`; skipped dates are not counted, an overnight shift counts in the month it starts); the card `#shCard` ("סיכום משמרות", `renderShifts()`, shown with `#expCard`: not in the day or up tabs, not printed) lists it. `toDoc(form,sun)` builds the db doc from the dialog (`form.date` is the picked date; if it is not a valid ISO date the weekday `form.day` in the week of `sun` is used); `detach(prev,f,sun,occ)` turns one occurrence of a recurring item into a one-off or deadline (new dated doc plus `skip` on the series).
     - Export: `semEvents` (every occurrence from `SEM.start` to `SEM.last`), `buildIcs` (one VEVENT per occurrence, `TZID=Asia/Jerusalem` with a VTIMEZONE block), `buildCsv` (Google import format), `zip1` (one stored, uncompressed file; `.ics` is not on the downloads allowlist, `.zip` is).
   - **Phone layout:** `PHQ = matchMedia('(max-width:600px)')` (width only, not `display-mode`; an iPhone turned sideways gets the desktop layout); `render()` toggles class `ph` on `<html>` from it and a `change` listener re-renders (a desktop falls back from `day`/`up` to `week`, not persisted). On a phone `view` is `day|week|month|up`: `day` (default on first run) shows `#dayCard`; `week` shows `#sum`, `#att` and the agenda `#agCard`, or the wide grid `#gridCard` while `wkGrid` (the `#gridTgl` toggle) is on; `month` shows the month with dots only (a deadline with a course is a hollow ring in that course's colour, so it differs from the course's solid class/exam dots; CSS under `.ph` hides the line text; `.ml` has `pointer-events:none`, so any tap in a cell reaches `dayClick`, which opens the day view); `up` shows only `#upCard` (30 items, a tap opens that day). `viewDay` is the picked ISO date; `goDay(d)` keeps `viewDay`, `viewSun` and `viewYm` in step, so the week and month tabs open on the picked day. `setView(v,date)` handles the tab bar (`date` opens the day view on that date; `up` is never stored in `wp.view`); `step(n)` is the prev/next/swipe move for the current view. In the day view `#dayList` lines are one `button[data-key]` each (`dayL` holds the lines): a class opens `openCancel`, an own item or deadline opens `openEdit`, exams (and classes in read-only modes) are plain `div`s; a deadline line has a 44px done checkbox (`data-done`). on a phone `#addBtn` is hidden and its job is done by the + in the tab bar (`#tabAdd`, between שבוע and חודש; it just clicks `#addBtn`; disabled when not editable or in the `up` tab) (day: `openAdd({day:dow(viewDay)})`, `viewSun` is already the picked day's week); `#addBtn` and `.nav` are hidden in the `up` tab. ## Conventions

- All user-facing copy is Hebrew. Pass user strings through `esc()` before writing them to `innerHTML`.
- The code is compact: short helpers (`$`, `pad`, `fm`, `tr`, `hrs`) and long one-line expressions. Match that style rather than reformatting.
- Delete takes two clicks (`delArmed`); there is no undo.
